# QianLesim UI 重构规范 · Work / Codex 交接

> 状态：**1.1.0 已按本规范实现；构建与发布结果需查询 Actions/Release，新 UI 真机验证待完成。1.0.1 是此前已验证切换的旧版基线。** 最后确认：2026-11-05。本文件说明用户实际决定，不能把效果图中未经实现的功能当作需求或现成功能。

## 1. 决策历程与最终选择

此前多轮 AI 效果图反复采用旧版 NekokoLPA 的布局，加上渐变霓虹、发光边框、半透明玻璃、星空/山脉背景和悬浮芯片。用户认为过度装饰，有明显“AI 味”，也不满意只换皮不重构。

后来用户要求：**“去除 Ai 味的设计，图标也可以重新设计简单科技感”**。新一轮深色极简 Android 风格设计已获用户反馈“可以，这种行”。

**最终采用的方向：**
- 克制的**石墨黑 / 深蓝灰**背景与卡片，少量清晰**科技蓝**作为操作强调色。
- 平面、简洁、符合真实 Android 应用的结构。低装饰、合理留白、精确对齐、清晰文字层级。
- 几何 eSIM 芯片标识，线条简练，缩小到通知栏/桌面图标仍清晰。
- 功能优先于炫技；原有成熟操作逻辑可以保留，但页面导航和信息组织可以重构。
- **禁止**星空、山脉、月亮、光波、强烈荧光描边、玻璃层叠/大面积透明、镜面 3D SIM 图标、悬浮宣传卡及营销海报式界面。

## 2. 最重要的操作约束：一张卡一个开关

用户明确指出：NekokoLPA 原版每个 eSIM 配置都有启用按钮，新增“切换”总按钮会让操作更繁琐。

- 每张已安装配置展示名称、运营商/必要元数据、当前状态及自己的**启用开关**。
- 点击未启用配置的开关，直接运行现有 eSIM 启用流程；**不要要求“点切换 → 选卡 → 再确认”**。
- 已启用配置在可用条件下可按原有保护策略处理停用。不能为了统一视觉删除原有 OMAPI 停用风险提示/保护，不能默认提供实际上不可用的关闭行为。
- 同一 eUICC 若硬件通常只能启用一个配置，成功切换后其他配置真实状态应相应反映；不要把本地开关立即变化当作硬件完成。
- 区分物理 SIM1/SIM2 卡槽、eUICC 设备及同一设备的多个 profile；保留多设备/外接读卡器能力。
- 操作期间显示清晰但不过度干扰的状态。需要根据真实读卡结果确认；出现通信问题时给出同步中/待确认/失败提示，不能一直 Loading 或展示虚假的成功。
- 原切换后的状态不同步 Bug：**用户在 1.0.1 版本反馈已修复**。本次 UI 重构不得回归；不要再主动修改底层切换协议来“重修”一个当前未复现的问题。

## 3. 组件与页面结构（指导性，不是要求新增所有页面）

### A. 首页：偏控制台，而不是花哨仪表盘

推荐布局（屏幕自上而下）：

```text
QianLesim                         ⋮
eSIM 管理工具

[SIM1 · eUICC]  [SIM2（不可用时明确置灰）]
设备摘要：配置数量 / 已知状态        详情 >

已安装配置 (N)
┌────────────────────────────────────────┐
│ [运营商图标] giffgaff           [ ● ] │
│               运营商 / 简要信息        │
│               ● 正在使用              │
└────────────────────────────────────────┘
┌────────────────────────────────────────┐
│ [运营商图标] Telna / Jetpac     [ ○ ] │
│               运营商 / 简要信息        │
│               ○ 未启用                │
└────────────────────────────────────────┘

[添加配置（沿用现有可用流程）]

导航：只保留已有真实可用的页面
```

- 主内容是**eSIM 配置列表和独立开关**，不必在首页复制大量 EID/存储细节。
- 启用配置用**小面积蓝色边框或明确的状态标签**区分；不要强光描边。
- 运营商图标允许复用现有图标来源，缺失时使用简洁统一的占位图标。
- 超长配置名称截断并提供详情查看；操作开关不能被挤出可点击区域。
- 无 eSIM、SIM2 不可用、设备读取失败、多个 eUICC、列表很多项均有合理展示。
- 不要为了复刻效果图而添加“统计”/“流量监控”/“切换历史”等不存在的数据页面。

### B. eUICC 详情：详细技术信息下沉

- 在有真实数据时展示 EID（默认脱敏）、复制操作、已知配置数量和存储数据。
- 显示 **free space / total space** 及单位时，先确认芯片/代码返回含义；不要在图表中误标“已用”“剩余”或编造百分比。
- 如提供配置详情或列表，要避免与首页功能重复；调用既有可靠 API。
- 高级调试、读写等敏感入口按已有权限及确认机制管理，不因 UI 重构改变安全语义。

### C. 设置页：原生列表感

- 标题、分组、小图标、清晰的行高与分隔线，无大面积背景插画。
- 保留项目已有可用设置，避免重复图标、花哨阴影和无意义的“功能卡”。
- 示例：外观、语言/通知（仅在确实有功能时）、简洁模式、刷新相关设置、调试与日志、关于。
- **现有“切换后自动刷新”是操作能力，不是设计稿里随意添加的假开关**；如果展示可控制开关，必须确实接入功能并保存选项。
- 关于页明确 QianLesim 是基于 NekokoLPA 的定制版，并保留开源许可与来源。

### D. 统计、历史记录页面

概念图可能画了统计卡片、切换次数、日期或空间圆环图。**这些是视觉占位，并没有用户授权把它们当作已完成/必须上线的功能。**
- 除非现有代码提供可信数据，不新增伪统计指标和假切换历史。
- 如果 Work 建议开发新功能，先与用户单独讨论范围，UI 重构本身不包含新数据采集或上传。

## 4. 建议的设计 Token（初稿，可基于实机可读性微调）

这些是**实施建议**，不是用户逐个确认过的精确色值：

| 用途 | 建议 |
| --- | --- |
| 页面背景 | `#0F1722` |
| 卡片背景 | `#1C2734` |
| 次级卡片/分组 | `#243141` |
| 分隔线 | `#344252` |
| 主要文字 | `#F1F5F9` |
| 次级文字 | `#A7B3C0` |
| 强调蓝 | `#2889E8` |
| 启用状态 | `#27C271` |
| 待确认状态 | `#E0A742` |
| 危险操作 | `#E35D65` |

排版优先采用现有 Android/React Native 可正常加载的系统字体与字重；字号层级约 22/17/14/12，间距采用 4 或 8 的倍数。建议圆角 12–16，细边框或轻微分隔，避免多层阴影和大面积全屏蓝光。

图标优先使用统一的简洁线性图标集；图标语义清晰并具有触摸热区。保留亮暗对比和无障碍字号，触摸目标一般不小于 44–48 dp。

## 5. App 图标重设计

- 新视觉：**扁平或极轻层次的几何 eSIM 芯片**，可由简化轮廓、触点和两三道等距线组成。
- 颜色：深色底 + 科技蓝/浅色线条，主色不超过 2–3 种。
- 避免旧版“芯片+发光行星轨道”、猫咪、3D/镜面/浮动芯片、复杂渐变与小字。
- 独立输出 Android launcher icon（包括自适应 foreground/background 与常规密度尺寸，按项目实际适配方式）、App 内图标以及预览。小尺寸下检查是否可辨。
- **不改变** Android 包名 `ee.nekoko.nlpa1`、签名集合、eSIM OMAPI 权限和既有升级路径。
- 图标最终定稿需结合实际桌面截图确认，不能只凭大型宣传稿决定。

## 6. 实施边界与 Work 的具体任务

1. 先读根目录 `AGENTS.md`、本文件、`docs/QianLesim-maintenance.md`，再检查当前导航、已实现页面、主题变量和配置开关逻辑。
2. 提出**保留现有流程、不增加虚假功能**的 UI 实现方案；区分仅视觉重构与需要动业务逻辑的变更。
3. 建立统一 design tokens 和可复用组件（列表项、状态点、开关、设备摘要、设置分组、空状态等），减少硬编码。
4. 先落地首页与设置，再完善 eUICC 详情和 App 图标；按真实设备截图做一次精简迭代。
5. 不需要为了 UI 变更大规模重写 LPA/OMAPI 层；原 1.0.1 版本及安装行为应作为回归基线。
6. 测试无设备/多设备、0/1/多配置、长名称、字体放大、浅/深色兼容（若有）、网络不可用、Loading、真实切换后的开关同步。
7. 版本及签名管理完全按 `AGENTS.md`，使用已有缓存构建。先类型检查再编译，最终 APK 发布后明确标记哪些只通过 CI、哪些通过真机。
8. 用户确认的是**设计方向**，不是对任意自动生成图的像素级承诺。提交前后提供真实 Android 截图供用户审阅。
